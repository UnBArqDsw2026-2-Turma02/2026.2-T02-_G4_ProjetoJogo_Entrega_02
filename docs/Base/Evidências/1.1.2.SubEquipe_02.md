A consolidação da modelagem deu-se com a elaboração do diagrama de classes final, projetado com base nos requisitos elicitaos, refinamentos refinados via Inteligência Artificial e nas diretrizes apresentadas na disciplina ("Arquitetura e Desenho de Software - Aula Modelagem UML Estática"). A construção da arquitetura orientada a objetos sustentou-se nas práticas descritas por Larman (2007), estruturando o mapeamento das entidades essenciais do domínio — como o gerenciador de ciclos Pomodoro e o mecanismo de evolução do bichinho virtual. Além disso, a aplicação rigorosa dos relacionamentos estáticos (herança, composição e agregação) e dos níveis de visibilidade garantiu a consistência das abstrações necessárias, fundamentando-se nas abordagens clássicas de engenharia e metodologias de design de software (Pfleeger, 2004; Zhu, 2005; Colorado.edu, 2008).

<details class="code-evidence" open>
<summary>Código-fonte Mermaid — Diagrama de Estados (48 linhas)</summary>

```mermaid
stateDiagram-v2
    %% Título: Diagrama de Estados — Ciclo de vida do Mascote
    %% (rastreável ao Diagrama de Classes: atributos nivelFome, nivelSaude, nivelSujeira, estadoSaude, estagioVida e métodos comer(), tomarRemedio(), adoecer(), sujar(), ganharXP())

    state "Saudável (estado inicial)" as Saudavel
    state "Faminto" as Faminto
    state "Sujo" as Sujo
    state "Doente" as Doente

    [*] --> Saudavel

    Saudavel --> Faminto : decaimento periódico\n/ [nivelFome <= limite]
    Faminto --> Saudavel : comer(alimento)\n/ nivelFome ↑

    Saudavel --> Sujo : sujar()\n/ [nivelSujeira > limite]
    Sujo --> Saudavel : darBanho()\n/ nivelSujeira = 0

    Saudavel --> Doente : adoecer()\n/ [nivelSaude < limite]
    Doente --> Saudavel : tomarRemedio(remedio)\n/ nivelSaude ↑

    Faminto --> Doente : fome prolongada\n/ adoecer()
    Sujo --> Doente : sujeira prolongada\n/ adoecer()

    note right of Doente
        Nota (rastreabilidade):
        A ideia de que negligenciar múltiplos
        atributos ao mesmo tempo acelera o
        adoecimento foi inspirada nos achados
        da Engenharia Reversa (Sprint 1):
        o fator de risco de saúde se acumula
        com fome/sujeira baixas.
    end note

    state "Sub-máquina independente — Evolução (estagioVida)" as SubMaquina {
        state "Filhote" as Filhote
        state "Jovem" as Jovem
        state "Adulto" as Adulto

        [*] --> Filhote
        Filhote --> Jovem : ganharXP(pontos)\n/ [acumulado >= limiar1]
        Jovem --> Adulto : ganharXP(pontos)\n/ [acumulado >= limiar2]
    }

    note right of SubMaquina
        Evolui em paralelo ao estadoSaude,
        disparada pelas sessões Pomodoro
        concluídas (ganharXP).
    end note
```

<details class="code-evidence" open>
<summary>Código-fonte Mermaid — Diagrama de Sequência (37 linhas)</summary>

```mermaid
sequenceDiagram
    %% Título: Diagrama de Sequência — Sessão Pomodoro concluída -> XP -> Evolução do Mascote
    %% (participantes derivados do Diagrama de Classes: Usuário, TemporizadorPomodoro, HistoricoTarefa, Mascote)

    actor Jogador as Jogador (ator)
    participant U as :Usuário
    participant T as :TemporizadorPomodoro
    participant H as :HistoricoTarefa
    participant M as :Mascote

    Jogador->>U: iniciarSessaoEstudo(temporizador)
    activate U

    U->>T: iniciarCronometro()
    activate T
    T->>T: conta regressiva (loop interno)
    T->>T: finalizarPomodoro() : tempoFocadoMin
    T-->>U: retorna tempoFocadoMin
    deactivate T

    U->>H: registrarSessao(tempo, tarefa)
    activate H
    H->>H: calcularOfensivaDiaria() : int
    H-->>U: retorna ofensiva atualizada
    deactivate H

    U->>U: receberXP(quantidade)

    alt
        U->>M: ganharXP(pontos)
        activate M
        M->>M: [acumulado >= limiar] atualiza estagioVida
    else [else] apenas acumula XP (sem evoluir)
        M-->>U: retorna estado atualizado
        deactivate M
    end
    deactivate U
```

</details>
