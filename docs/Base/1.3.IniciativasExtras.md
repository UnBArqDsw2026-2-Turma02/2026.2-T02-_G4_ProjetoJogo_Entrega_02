# 6. Requisitos de Software

## 6.1 Requisitos Funcionais

| ID | Nome | Descrição | Prioridade |
| :--- | :--- | :--- | :---: |
| **RF01** | **Executar sessões de Pomodoro** | O sistema deve permitir a inicialização, pausa, retomada e finalização de ciclos de foco configuráveis baseados na técnica Pomodoro. |  |
| **RF02** | **Categorizar atividades por CategoriaXP** | O sistema deve permitir associar tags temáticas (`INTELECTUAL`, `SABEDORIA`, `ZEN`, `ATLETICO`, `HIDRATACAO`) às sessões do temporizador Pomodoro. |  |
| **RF03** | **Registrar frequência e tempo de foco** | O sistema deve contabilizar o tempo total acumulado e a quantidade de ciclos de Pomodoro concluídos com sucesso por categoria de atividade. |  |
| **RF04** | **Acessar atalhos do Pomodoro** | O sistema deve disponibilizar atalhos de acionamento rápido na tela principal para iniciar uma sessão de foco sem navegações complexas. |  |
| **RF05** | **Realizar check-in de hábitos** | O sistema deve permitir que o usuário marque como concluídos os hábitos cadastrados em sua rotina diária. |  |
| **RF06** | **Contabilizar ingestão de água** | O sistema deve oferecer um contador em mililitros (ml) para registrar e validar a meta diária de ingestão de água. | |
| **RF07** | **Registrar hábitos por categorias temáticas** | O sistema deve permitir o cadastramento e acompanhamento específico de rotinas vinculadas às categorias de XP (estudos, leitura, saúde mental, exercícios e hidratação). |  |
| **RF08** | **Calcular sequências de hábitos (*streaks*)** | O sistema deve registrar e contabilizar o número de dias consecutivos em que o usuário cumpre seus hábitos e a sequência geral da conta. |  |
| **RF09** | **Configurar dias ativos do hábito** | O sistema deve permitir definir os dias da semana (`DiaSemana[1..7]`) em que o hábito é cobrado, permitindo dias de descanso programados sem quebrar a sequência. |  |
| **RF10** | **Congelar sequência de hábitos (*Streak Freeze*)** | O sistema deve permitir acionar o congelamento da sequência de um hábito, aplicando um tempo de recarga (*cooldown*) obrigatório de 7 dias entre acionamentos. |  |
| **RF11** | **Distribuir experiência no vetor de XP do Pet** | O sistema deve conceder pontos de XP e armazená-los no vetor de 5 posições do `PetVirtual`, correspondentes às categorias do hábito ou sessão concluída. |  |
| **RF12** | **Processar evolução por afinidade** | O sistema deve transformar graficamente a forma assumida pelo `PetVirtual`, selecionando-a pela maior afinidade no vetor de XP ou aplicando a forma `DESMOTIVADO` em dia sem atividade registrada. |  |
| **RF13** | **Desbloquear conquistas e selos** | O sistema deve avaliar marcos globais de desempenho (sequências acumuladas, total de Pomodoros) e conceder selos e bônus de XP ao pet virtual. |  |
| **RF14** | **Consultar histórico de desempenho** | O sistema deve disponibilizar consultas e visões consolidadas do histórico de tempo de foco, taxa de cumprimento de hábitos e consumo de água. |  |
| **RF15** | **Autenticar e gerenciar conta de usuário** | O sistema deve permitir a identificação única da conta do usuário via `idUsuario` (UUID) e gerenciamento de perfil. |  |
| **RF16** | **Apresentar tutorial interativo (Onboarding)** | O sistema deve exibir um guia no primeiro acesso orientando o usuário sobre as ferramentas de produtividade e evolução do pet. |  |
| **RF17** | **Navegar via interface intuitiva** | O sistema deve permitir navegação fluida entre os menus de foco, hábitos, pet virtual e histórico com respostas visuais fluidas. |  |

## 6.2 Requisitos Não Funcionais

| ID | Categoria | Descrição | Métrica / Critério de Aceitação |
| :--- | :--- | :--- | :--- |
| **RNF01** | **Usabilidade** *(URPS+)* | Eficiência do Onboarding para novos usuários. | Pelo menos **85% dos novos usuários** devem concluir o tutorial interativo e realizar a primeira sessão de Pomodoro em **menos de 3 minutos** na primeira tentativa sem auxílio. |
| **RNF02** | **Usabilidade** *(URPS+)* | Tempo de resposta do feedback da interface. | Toda ação de check-in, ingestão de água ou acionamento de temporizador deve fornecer retorno visual animado e sinal tátil/sonoro em no máximo **200 ms**. |
| **RNF03** | **Desempenho** *(URPS+)* | Latência na transição de telas e menus. | O tempo de transição entre menus e navegação da interface não deve ultrapassar **300 ms em 95% das interações**. |
| **RNF04** | **Desempenho** *(Sommerville)* | Consumo de recursos computacionais em segundo plano. | A execução contínua do temporizador Pomodoro em segundo plano deve consumir **no máximo 60 MB de RAM** e **menos de 5% de CPU**. |
| **RNF05** | **Confiabilidade** *(Sommerville)* | Persistência local e resiliência (*Offline-First*). | O estado do pet, o progresso dos hábitos e o vetor de XP devem ser salvos localmente a cada alteração ou a **cada 60 segundos**, utilizando UUIDs para garantir **0% de perda de dados** e suporte a sincronização. |
| **RNF06** | **Restrição de Design** *(URPS+ "+")* | Fidelidade estética *Pixel Art* e renderização. | A interface da tela do pet e ícones deve ser renderizada com escalonamento por inteiros (*nearest-neighbor*) sem interpolação borrada, mantendo taxa de quadros de **60 fps**. |
| **RNF07** | **Suportabilidade** *(URPS+)* | Compatibilidade com sistemas operacionais móveis. | O aplicativo deve funcionar sem erros fatais em **100% dos dispositivos homologados** com **Android 8.0+** e **iOS 13.0+**. |
| **RNF08** | **Arquitetura** *(Padrão)* | Unicidade e flexibilidade de identificadores. | Todas as entidades principais (`Usuario`, `SessaoPomodoro`, `Habito`, `ContagemDeAgua`, `Conquista`) devem utilizar IDs do tipo **`String`** (UUIDs) para permitir geração descentralizada no cliente. |

## 6.3 Regras de Negócio

| ID | Tipo de Regra | Descrição Detalhada | Requisitos Impactados |
| :--- | :--- | :--- | :---: |
| **RN01** | **Causa e Efeito / Computacional** | **Conversão de Produtividade em Experiência do Pet:**<br />• Cada sessão de Pomodoro (25 min) concluída com sucesso concede **+50 XP** direcionados à categoria associada à tag da atividade.<br />• Cada registro de ingestão de água (250 ml) credita XP na categoria `HIDRATACAO` e contabiliza no volume consumido do dia (meta padrão de 2.000 ml).<br />• Cada check-in diário de hábito concluído credita XP na categoria cadastrada e incrementa a sequência (*streak*) do hábito. | RF01, RF03, RF05, RF06, RF08, RF11 |
| **RN02** | **Derivação / Regra de Cálculo** | **Mapeamento do Vetor de Experiência por Categoria (`CategoriaXP`):**<br />Os pontos de experiência são acumulados estritamente em um vetor de 5 posições no `PetVirtual`, onde o índice (0 a 4) corresponde ao ordinal do enum `CategoriaXP`:<br />• `0 = INTELECTUAL` (Estudos, Trabalho, Foco)<br />• `1 = SABEDORIA` (Leitura, Cursos, Aprendizado)<br />• `2 = ZEN` (Meditação, Saúde Mental, Mindfulness)<br />• `3 = ATLETICO` (Exercícios, Esportes, Atividades Físicas)<br />• `4 = HIDRATACAO` (Consumo diário de água) | RF02, RF07, RF11, RF12 |
| **RN03** | **Restrição de Operação** | **Gestão de Sequências (*Streaks*) e Dias de Descanso:**<br />• A sequência (*streak*) de um hábito aumenta em +1 a cada dia de cumprimento.<br />• A quebra de sequência só ocorre se o hábito não for realizado em um dia cadastrado no atributo `diasAtivosSemana : DiaSemana[1..7]`. Dias não marcados como ativos são ignorados na verificação de inatividade. | RF08, RF09 |
| **RN04** | **Restrição de Operação / Temporização** | **Regra de Cooldown para Congelamento de Streak:**<br />• O usuário pode acionar o congelamento da *streak* para preservar a sequência em um dia não cumprido.<br />• O congelamento só é permitido se `(dataAtual - dataUltimoCongelamento) >= 7 dias` (`diasCooldownCongelamento = 7`). Caso contrário, o acionamento é bloqueado para evitar abusos. | RF08, RF10 |
| **RN05** | **Dedução / Regra Central** | **Matriz de Evolução por Afinidade Personalizada de XP:**<br />• **Escopo:** o `PetVirtual` é criado diretamente na fase adulta. A enumeração `FasePet`, que previa as evoluções bebê, criança, adolescente e adulto, foi removida por decisão da reunião geral entre os subgrupos, adequando o escopo ao prazo real de implementação.<br />• **Mecanismo de Seleção da Forma:** `verificarEvolucao()` dispara `determinarEvolucao()`, que analisa o vetor de XP de 5 posições e a categoria retornada por `calcularAtividadeMaxima()`. As guardas são mutuamente exclusivas e a forma é reavaliada a cada verificação:<br /> - *NEUTRO:* nenhuma `CategoriaXP` predominante — estado de uma conta nova, com `vetorXP` zerado.<br /> - *ESTUDIOSO:* predomínio de XP no índice `0 (INTELECTUAL)`.<br /> - *LEITOR:* predomínio de XP no índice `1 (SABEDORIA)`.<br /> - *ZEN:* predomínio de XP no índice `2 (ZEN)`.<br /> - *ATLETICO:* predomínio de XP no índice `3 (ATLETICO)`.<br /> - *HIDRATADO:* predomínio de XP no índice `4 (HIDRATACAO)`.<br /> - *DESMOTIVADO:* dia sem atividade registrada. | RF11, RF12 |
| **RN06** | **Estímulo e Resposta** | **Avaliação e Concessão de Conquistas Globais:**<br />• As conquistas são avaliadas de forma independente dos hábitos.<br />• Quando `validarRequisitoGeral(usuario)` retorna `true`, a conquista é marcada como desbloqueada (`foiDesbloqueada = true`), a data de desbloqueio é salva e um bônus de XP é creditado no `PetVirtual`. | RF13 |
